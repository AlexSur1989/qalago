# Процедура доступа, безопасности и инцидентов ПД

**Статус:** DRAFT — LEGAL REVIEW REQUIRED  
**Версия:** 2026-10-03-draft-1

## 1. Доступ к ПД

- Выдача доступа к production БД и admin — только уполномоченным лицам по заявке руководителя.
- Least privilege; периодический пересмотр прав (**LEGAL REVIEW REQUIRED** — периодичность).
- Запрет использования production данных в dev без обезличивания.

## 2. Конфиденциальность персонала

NDA / обязательства конфиденциальности для сотрудников и подрядчиков — **LEGAL REVIEW REQUIRED**.

## 3. Логирование

AuditLog для админ-действий; server access logs — хранение **LEGAL REVIEW REQUIRED**.

## 4. Обнаружение инцидентов

Мониторинг аномалий, сообщения от пользователей, alerts хостинга — по мере внедрения.

## 5. Эскалация

1. Обнаружение → ответственный IT/безопасность.  
2. Классификация (SecurityIncidentSeverity).  
3. Содержание и устранение.  
4. Уведомление руководства оператора.

## 6. Уведомление регулятора и субъектов

**LEGAL REVIEW REQUIRED** — пороги, сроки, форма уведомления уполномоченного органа и субъектов ПД.

## 7. Сохранение доказательств

Фиксация времени, затронутых систем, объёма данных; без публичного раскрытия exploit-деталей.

## 8. Post-incident

Запись SecurityIncident status POSTMORTEM; корректирующие меры.
