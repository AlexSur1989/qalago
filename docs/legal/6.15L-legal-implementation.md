## Acceptance matrix (technical)

| Audience / flow | Required when published | Source enum | Backend enforcement |
|-----------------|-------------------------|-------------|---------------------|
| Platform access (USER) | Terms + Privacy (+ PD consent if `LEGAL_REQUIRE_PERSONAL_DATA_CONSENT=true`) | LOGIN | `LegalAcceptanceGuard` |
| Platform access (BUSINESS) | Above + Business Terms | LOGIN | Guard + `/legal/current` |
| Business application submit | Business Terms | BUSINESS_APPLICATION | `assertBusinessApplicationLegal` (only if BT published) |
| Plan purchase | Public Offer | CHECKOUT | `assertCheckoutLegalAcceptance` when `LEGAL_ENFORCE_CHECKOUT=true` |
| Ad order | Offer + Advertising Terms | CHECKOUT | same |

## Locale

- Guard and checkout use `x-qalago-locale` / `Accept-Language` → `LegalLocale` (`legal-locale.util.ts`)
- Acceptance rows store client `locale`; **no reaccept on UI language change alone**

## Re-consent

- Unchanged: new `LegalDocument.version` + published doc → pending until new `LegalAcceptance` row; history retained

## Publication validation

- `publishDocument` rejects unresolved placeholders (`[OPERATOR_*]`, `[REFUND_POLICY…]`, etc.)
- Draft pack **cannot** be published as-is

## Env flags

| Variable | Default | Effect |
|----------|---------|--------|
| `LEGAL_REQUIRE_PERSONAL_DATA_CONSENT` | off | Adds PD consent to platform mandatory set when `true` |
| `LEGAL_ENFORCE_CHECKOUT` | off | Blocks plan/ad purchase if published checkout docs not accepted |

## 6.15L.2A — Contextual acceptance UX

Clients gate **submit / plan purchase / ad order** on current **published** documents before calling the API. Backend enforcement unchanged (`assertCheckoutLegalAcceptance`, `assertBusinessApplicationLegal`).

### Context matrix

| Context | Required types (when published) | Acceptance source |
|---------|-----------------------------------|-------------------|
| `BUSINESS_APPLICATION` | `BUSINESS_TERMS` | `BUSINESS_APPLICATION` |
| `PLAN_PURCHASE` | `PUBLIC_OFFER` | `CHECKOUT` |
| `AD_PURCHASE` | `PUBLIC_OFFER`, `ADVERTISING_TERMS` | `CHECKOUT` (one row per doc) |

### Client matrix

| Flow | Business Web | Mobile Owner |
|------|--------------|--------------|
| Business application submit | `/onboarding/apply` | `business_apply_screen` |
| Plan purchase | `/plan` | `/owner/plan` |
| Ad order | `/monetization/checkout` | `monetization_order_confirm_screen` |
| Ownership claim | N/A (no BT assert on backend) | N/A |

### API

- `GET /api/v1/legal/required?context=…&locale=RU|KK` — pending + published metadata (auth, `@SkipLegalAcceptance`).
- `POST /api/v1/legal/me/accept-required` — optional `context`; validates items against that context’s pending list and acceptance source.

### Version / race

If a document version changes between UI accept and purchase, backend returns `LEGAL_ACCEPTANCE_REQUIRED` or `LEGAL_VERSION_STALE`; clients refresh requirements and show re-consent copy (RU/KK).

### Unpublished

- **Business application:** no block unless `BUSINESS_TERMS` is **PUBLISHED** (unchanged).
- **Checkout:** enforcement only when `LEGAL_ENFORCE_CHECKOUT=true`; unpublished required doc → `LEGAL_DOCUMENT_NOT_PUBLISHED`.
- Clients do not accept DRAFT rows; UI hidden when no published current doc.
