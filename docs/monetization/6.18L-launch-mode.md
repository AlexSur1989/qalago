# 6.18L — Launch mode and monetization kill switch

## Purpose

Backend-controlled **MonetizationMode** for Google Play first release and operational toggles **without** mutating canonical billing (`Business.planTier`, `Business.planExpiresAt`, payment history).

## Modes

| Mode | Purchases | Launch uplift | Typical use |
|------|-----------|---------------|-------------|
| **NORMAL** | Plans + ads allowed | No | Production monetization |
| **LAUNCH** | Blocked (403 `MONETIZATION_DISABLED`) | Yes — MAX(canonical, launch profile) | First public release |
| **DISABLED** | Blocked | No — canonical limits only | Kill switch |

Source of truth: global feature flags `monetizationPurchasesEnabled`, `freeLaunchAccessEnabled` via **MonetizationModeService** (no extra schema).

Mapping:

- Purchases **on** → **NORMAL** (launch flag ignored).
- Purchases **off**, launch **on** → **LAUNCH**.
- Both **off** → **DISABLED**.

## Canonical vs effective plan

- **Canonical:** stored tier + expiry; never rewritten for launch.
- **Effective limits:** `PlanLimitsService` returns merged limits in LAUNCH; optional `launchAccessActive` on plan status DTO.

Launch profile: BASIC-like operational caps; **advertisingDiscountPercent = 0**, **monthlyAdBonusKzt = 0**; no home/category ad inventory or campaign credits.

Paid businesses (BASIC/PREMIUM/VIP): `effectiveLimits = max(actual, launch)` — never downgrade.

## Purchases

- **Plans:** `PlansService.createPlanPurchase` / mock checkout — guarded before `PlanPayment` creation.
- **Ads:** `OrderService.createOrder` — guarded before order/payment/campaign creation.
- Admin confirmation of existing pending plan payments remains allowed.

## Existing campaigns

ACTIVE/SCHEDULED campaigns continue to serve; analytics and history remain readable.

## Config propagation

- **GET `/app-config`:** `monetizationMode`, `canPurchasePlans`, `canPurchaseAds`, `launchAccessActive`, `configRevision`.
- **GET `/platform-features`:** same monetization fields for Business Web.
- **Admin:** Settings → Monetization (SUPER_ADMIN only) patches `monetizationMode`; bumps `configRevision`.

Clients must not hardcode mode; on config failure, treat purchases as **disabled**.

## Client UX (summary)

- **Mobile / Business Web:** hide buy/upgrade/renew and ad checkout entry points when mode ≠ NORMAL; LAUNCH shows launch badge/banner; history and campaigns remain visible.
- **Admin:** pricing, confirmations, moderation unchanged.

## Legal

When mode ≠ NORMAL, do not request **PUBLIC_OFFER** / **ADVERTISING_TERMS** for blocked checkout flows.

## Google Play first release

Recommended mode: **LAUNCH** — closes RELEASE-008 (no purchasable plans/ads, no fake subscriptions, useful owner features via launch profile).

### First-release gate (operator QA)

Non-destructive checks (do **not** change runtime mode):

- **Script:** `node scripts/check-google-play-launch-mode.mjs [apiBase]` — reads public `GET /app-config`; **exit 0** only when `monetizationMode === LAUNCH`, purchases off, `launchAccessActive === true`.
- **Admin API:** `GET /api/v1/admin/platform-features/google-play-launch-check` (ADMIN / SUPER_ADMIN) — same `pass` / `actualMode` JSON.

Expected before first Play release: **PASS** with **LAUNCH**. **NORMAL** or **DISABLED** → **FAIL** (fix via Admin → Monetization).

## Direct routes and deep links

Backend always rejects new purchases when mode ≠ NORMAL. Clients must not show buy/checkout UI on direct URLs.

### Business Web

| Route | NORMAL | LAUNCH / DISABLED |
|-------|--------|-------------------|
| `/plan` | Purchase CTAs | Read-only plan + history; no checkout |
| `/monetization` | Full hub | History/campaigns; no catalog CTAs |
| `/monetization/products` | Catalog | Unavailable panel |
| `/monetization/products/[code]` | Checkout flow | `PurchasesUnavailablePanel` |
| `/monetization/packages` | Packages | Unavailable panel |
| `/monetization/packages/[code]` | Quote + buy | Read-only unavailable (no quote fetch) |
| `/monetization/checkout` | Checkout | Unavailable (no quote) |
| `/monetization/vip-creative` | VIP upload | Unavailable |

Platform config load failure → purchases treated as **disabled** (fail-closed).

### Mobile

Deep links / routes: `/owner/plan`, `/owner/promote`, `/owner/promote/:productCode`, `/owner/promote/package/:code`, `/owner/promote/vip-creative`, `/owner/monetization/confirm`.

When `canPurchaseAds` / `canPurchasePlans` from **`/app-config`** are false: show **`MonetizationPurchasesUnavailableBody`** (optional link to campaigns); no price-to-buy actions. Missing config → same fail-closed defaults.
